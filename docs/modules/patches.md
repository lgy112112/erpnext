# Patches 模块（数据库迁移补丁）

## 概述

`patches/` 存放 ERPNext 数据迁移与修复脚本。业务流程变更如果涉及：
- 字段重命名
- 数据回填
- 状态修复
- 历史数据迁移

通常需要同时新增 patch，并在 `patches.txt` 注册。

## 规模（当前仓库）
- 约 410 个 Python patch 脚本
- 版本目录：`v4_2` 至 `v16_0`（共 12 个版本目录）

## 关键文件
- `erpnext/patches.txt` — patch 执行索引（按版本与阶段组织）
- `erpnext/patches/v*/` — 各版本 patch 目录

## 修改业务流程时何时需要 patch

以下情况通常需要新增 patch：
- 变更状态字段含义或状态枚举
- 新增/替换业务字段，需迁移历史数据
- 修复历史单据的数量/金额/引用关系
- 修改默认配置，需要回填旧站点数据

## 常见风险

- 代码已改但历史数据未迁移，旧数据在 `validate/on_submit` 报错
- patch 写入顺序不对，依赖字段尚未创建
- patch 未幂等，重复执行失败
- patch 只修数据，不兼容已取消/异常状态单据

## 建议实践（给 LLM）

1. 先确认是否真的是 schema 变更（可能只需兼容旧值）
2. patch 保持幂等（可重复执行）
3. 在 patch 中显式过滤取消单据/无效数据
4. patch 文件名反映动作（如 `migrate_*`, `rename_*`, `set_*`）
5. 别忘记同步更新 `patches.txt`
